# 全量命名 OSM 对象定位核对

基准日期：2026-10-14。只为主台账中尚未定位的官方 A 级记录与 PRD 明确命名候选生成位置候选；本文件和 `data/extra-geocodes.json` 不改写 `data/pois.json`。

## 数据与方法

- 扫描源：`data/raw/hunan-latest.osm.pbf`，Geofabrik 湖南 OSM 快照（[数据页](https://download.geofabrik.de/asia/china/hunan.html)），ODbL-1.0，署名 © OpenStreetMap contributors。
- 完整解析本地 PBF 中带 `name`、`name:zh`、`alt_name` 或 `alt_name:zh` 的 node 和 way；共检查 27,036 个命名 node、81,020 个命名 way。没有读取 relation。
- 使用 `scripts/link_pois.py` 的 `normalized()` 做规范化精确匹配；只额外接受下列有政府来源支持的别名。模糊相似度不产生定位结果。项目现有 ALIASES 中其余映射未据此自动匹配。
- node 坐标直接取 OSM WGS84 location；way 坐标是 `locations=True` 得到的所有有效节点经纬度均值，属于对象几何代表点，不是入口。JSON 保留原 OSM tags、类型、ID 和坐标。
- 候选坐标通过湖南省范围边界检查（经度 108–115、纬度 24–31）；全部记录均通过。该边界只用于异常值筛查。

## 结果

- 未定位目标：110 条（官方名录 64，PRD 候选 46）。
- 新增定位候选：32 条 OSM 对象记录，覆盖 14 个台账目标；规范化精确匹配 30 条，来源核验别名 2 条；仍有 96 个目标未命中。
- OSM 扫描与几何：无 node 缺坐标，0 条命名 way 缺完整几何。候选仅供主代理审阅和合并，不等同景点边界或入口核验。
- 长沙范围核对：32 条对象候选均按 `data/map.json` 的世界米边界多边形做 point-in-polygon；WGS84 转换使用原点 (113, 28.2) 与地球半径 6,371,008.8 m。范围内 25 条，范围外 7 条。范围外记录仍留在机器候选中并标为 `inChangshaBoundary=false`，不可合并为长沙景点位置。

## 已核验别名与边界

- **杨开慧纪念馆景区 / 杨开慧故居**：湖南省政府[《杨开慧故居》](https://hunan.gov.cn/hnszf/c101474/202108/t20210827_20403654.html)将杨开慧纪念馆景区描述为含故居、陵园、陈列馆等组成的场所。只对名称明确为“杨开慧纪念馆”的台账目标应用该别名；位置仍是对应 OSM 对象候选。
- **洋湖湿地 / 洋湖国家湿地公园**：湖南省林业局[页面](https://lyj.hunan.gov.cn/lyj/xxgk_71167/gzdt/mtkl/202602/t20260206_33911784.html)采用“洋湖国家湿地公园”名称，支持该名称用于“洋湖湿地”目标的匹配。
- **隆平水稻博物馆与隆平水稻文化园**：不作为别名处理。湖南省政府[开馆报道](https://www.hunan.gov.cn/hnszf/hnyw/zwdt/201909/t20190928_10468675.html)明确博物馆位于园区内，两者是园区与馆的不同对象；若源 PBF 只标其中之一，不据此把它当作另一个对象的别名。
- 任何未被上述官方材料支持的别名、近似拼写或模糊候选均未自动写入定位结果；需另行核源。

## 产物与重现

- 机器候选：`data/extra-geocodes.json`。每条记录包括目标 ID、OSM type/ID、名称、全部 tags、WGS84 坐标、匹配方法；别名记录带来源 URL。
- 重跑：在仓库根目录执行 `python scripts/extract_named_pois.py`。脚本通过 `.python-deps` 导入 osmium，并以 ASCII 相对路径 `data/raw/hunan-latest.osm.pbf` 配合 `locations=True` 解析 way 几何。
- OSM 数据由社区贡献，名称/坐标可能过时或不精确；当前结果不能证明全长沙景点台账完整，也不能证明具体游览入口、步行开放或景点还原完成。
