# R06 游戏设计理论与技能探图

日期：2026-10-16。用户本轮纠正：**“这样效率太低了，探图优先寻找理论、skill之类的。”** 本轮撤回“逐界面试玩作为探图主线”；先补足理解、判断和制作方法，试玩用于核对实际机制和关键未知。开放学习继续允许出现原有分类之外的问题，不把本文条目当成研究边界。

本轮成果是制作方法与实施依据的修订，未改游戏源码。全长沙连续地图、真实尺度、城区至远郊步行、Minecraft风格、摄影/路人、85分还原线保持；不安排真人。

## 1. 为什么更换探图方法

R04/R05已走通示例多个实际流程。本轮继续白云山等入口后，新增认识较少，时间却转向加载、Canvas点击和重复导航。用户指出效率问题成立：操作回执能核实行为，不能独自补齐游戏设计知识。继续增加截图或换试玩入口无法解决这个原因。

因此本轮改用作者/教材/论文的一手说明和技能原文，研究它们为什么这样设计、何时适用、怎样组织制作。已有MDA、MIT、TOEM、Alba、A Short Hike和Game Studio资料复用，不把旧阅读计作新发现。理论也需要与项目事实核对；作者经验、文献综述和社区skill都不是本项目已成功的证明。

## 3. 新认识、撤回判断、已经采用的改进

以下“项目改进”是结合原始需求与既有问题作出的推论，区别于来源原话。它们已经进入PRD和制作方案，不只是候选链接。

| 新依据 | 被撤回或修正的判断 | 本项目采用的决定 | 如何核对是否有帮助 |
| --- | --- | --- | --- |
| 教材的Research章节把观察、研究作者解释和拆解结合；本轮加载与操作排障产出有限 | 持续亲自点更多页面就会自然提高设计理解 | 理论/作者经验/skill原文优先；已有实玩先复用。带着学到的解释再核对关键行为，渠道排障不长期占用研究主线 | 每份新增资料须写出认识变化或可用方法；没有新增价值的访问如实归档并结束，不以数量结案 |
| Firewatch原始讲稿说明，其吸引力所依赖的美术和对白不能由灰盒证明 | 先功能全通、再逐项补美术，就能顺利形成观光游戏；技术通过可推进质量判断 | 使用同一真实场所的代表性可玩片段，联合校准空间、美术、角色/镜头、可观察内容、人物、摄影和反馈；灰盒仅回答几何/通行等它能回答的问题 | 在普通行走镜头及实际保存照片中对照实景/参考；缺场景/人物质量时不宣布体验成立。样板仍不替代全市交付 |
| Goose Game作者摘要以真实地点勘察组织关卡 | 先用想象搭通用广场/商铺，再贴长沙标签就是足够的前期工作 | 从可核实实景提取体量、空间关系、入口、视线、路径和日常用途，再决定方块表达；不套用其拼贴地理的方法改变长沙 | 场所身份、入口/层位与资料逐项对应；玩法文案不能弥补错误地理 |
| 手感综述讨论运动、碰撞、输入语境、镜头和反馈相互作用 | 移速调大、鼠标能转、FPS高，就接近示例手感；动画/音效是最后装饰 | 将角色、控制、镜头与脚下空间作为联合制作对象；检验起停/转身/斜走、坡台/狭窄处、摄影/面板进入返回的连续结果，动画和脚步与动作一致 | 正常键鼠录像并记录操作→角色/镜头反应；配合时间/位移核对。只改参数或帧率不能关闭主观质量缺口，不编造统一最佳参数 |
| 环境美术章节从可读性、聚组、材质识别和整体关系讨论细节 | 多加小方块、提分辨率和饱和度就会更清晰精细 | 先校准大体量、轮廓/明暗和材质家族，再处理细节；玩家/路人、街具、建筑与中文HUD在同一实际受光场景审查 | 近/中/远景及行走时检查辨识、入口可见性和画面层级；不得为简化画面抹掉真实招牌/结构，也不复制竞技射击的视觉规则 |
| Skill中的通用循环、奖励与团队流程并非都适合当前游戏 | 文档叫game-design就可以自动采用其全套判断 | 采用有明确帮助的分析/交付结构，按原需求过滤引擎、经济、数值、人力与范围默认；规则冲突处不执行 | 看它是否帮助解释真实玩家动作、场所关系、依赖和结果，而非是否填满模板 |

MDA和Fullerton提供的是学习与设计视角，不是“必须只有一个30秒循环”的依据。玩家自主观察、辨路、构图和留下记录本身可以有价值；增加任务、升级或货币须另有与长沙游览有关的理由。R04/R05已撤回把“拍一张/聊一次/走100米”直接推广成城市玩法的判断，本轮不重新接受它。

## 5. 已落实的制作架构与实施安排

这是由本轮依据支持的制作方法，不是新设的探图题目全集或固定模块顺序。

1. **设计交接写行为与因果。** 对拟实施内容写清：依据/原始需求→玩家所处情境及自主选择→可见行动与结果→空间/资产/状态依赖→失败处理→证据。现有共享状态只承担一致性；先核对玩法含义再映射到事件，不能反过来按数据库方便决定玩法。
2. **空间与体验共用真实场所。** 继续在已授权的五一广场及经典场景制作中，联合处理实景体量/层位/入口、视觉组成、人物尺度/镜头、可观察机位和路人语境。真实入口资料冲突没有解决前，不写虚构导航；设计需与已有全市坐标、碰撞、可见主体、旅途身份对接。
3. **代表性可玩片段承担质量校准。** 不是独立小地图，也不是只含一条演示路线：普通行走、转向、绕行/返回、停留构图、人物活动、保存回看在同一场景中成立。灰盒结果保留作空间检查，场景图、操作录像与照片原件共同回答体验问题。白天/夜间、近远景按PRD复核，未达到85分就记录未通过。
4. **资产成套检查，再推广。** 复用部件、材质、角色和UI必须在同一游戏光照/尺度下比较；地标主体和长沙独特内容逐处校正。可用现有场景及工具，不先造新编辑器、测试平台或迁移引擎。以真实资源/运行约束形成必要架构改动。
5. **实现后用适合的证据检验。** 功能检查回答动作是否成立；实景/几何/画面对照回答还原；普通输入录像与运动数据回答响应/一致性；代理观察不宣称真人喜欢、好玩或普遍手感已获证实。禁止真人安排继续生效。

PRD 1.3、9.2、M-1/M1正文与制作方案已同步修改；没有只在台账末尾追加纠正、保留旧串行规则。通用理论/skill检索在本轮结束，已有材料进入制作判断与交接；仅当具体实施被新的关键未知影响时再针对性取证。不能把继续补书单设为开工前提，也不能仅为显得推进就重新挑一个按钮小改。

## 6. 被中止的试玩如实归档

用户指出效率问题后，本轮自建的5个浏览器会话全部关闭；原始截图/动作不删除，也不再制作新的大型画廊。详见[会话索引](../artifacts/open-game-research-20261016/round06-evidence-index.json)。

- 示例白云山：24状态/76动作。普通键鼠登山、树/栏杆受阻与绕行、摄影/任务页已操作；最终游戏行走计数1753米、照片1、到访2/43。白云登高任务仍0/1。摩星岭碑文382米与HUD约295米不一致，原因未查明；不推定真实地形高度。自拍后朝向变化、远处中信识别仅保留观察，未作故障归因；未乘索道。任务类别此前已见，不计为全新发现。
- Mine Blocks：直达嵌入页报PHP错误；作者门户只走到菜单/新建世界过渡，未成功进入可行走世界。不是同类玩法已体验。
- Shutterbug：作者页/直达页只到加载与Play入口，未实际验证窗口移动/缩放摄影。作者说明可记录，不能写成实际核心体验。

上述试玩增加的认识不足以支持新的城市玩法或架构决定，不强行生成“改进点”。失败与学习成本促成本轮方法纠正，不将24状态或39项目录当作游戏推进量。
