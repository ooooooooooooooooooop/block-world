## 1. 产品定义与已确认需求

《方块长沙》让玩家打开网页，就能进入一座有长沙地貌、建筑和街巷特征的方块城市：沿湘江散步、走进老街、登山看城、遇见路人，并把喜欢的画面拍下来。

产品的核心吸引力是：**“我能走进一整座方块长沙，自由游览、遇见路人，并拍下值得留下的城市片段。”** 全市高还原是基础门槛，覆盖每个应交付景点及沿途城市环境；在此基础上，连续行走、摄影、生活氛围和操作完成度共同构成游戏体验。

| 类型 | 本版定义 |
| --- | --- |
| 用户已确认 | 首发城市为长沙，覆盖长沙全市景点 |
| 用户已确认 | 全市连续地图，可以从城区一路步行到远郊；景点之间的道路属于体验内容 |
| 用户已要求 | 我的世界风格、城市行走、拍照、有路人、景点高度还原 |
| 本稿设计选择 | 原创方块美术；单人游览；电脑浏览器优先；第三人称默认，可切第一人称 |
| 本稿设计选择 | 地理尺度原则上 1:1；全域地形与路网连续；景点逐处精制；普通建筑按真实位置和体量程序化生成 |
| 本稿设计选择 | MVP 包含昼夜、固定脚本 NPC、相册、地图导航、游览记录、本地存档 |
| 后续版本 | 手机触屏完整适配、多人联机、可驾驶交通工具、云相册、开放式 AI 对话 |

“我的世界风格”在本项目中指方块构成、像素材质、简洁人物和自由行走的视觉感受。项目使用原创模型、材质、角色、音效和界面，正式名称暂定《方块长沙》。

### 1.1 MVP 要解决的核心问题

先满足全市还原准入线，再回答以下体验问题：

1. 玩家能否沿连续的真实城市空间，从街区走向江岸、山地和远郊，自然发现下一处可游览内容？
2. 街景、角色、路人、光照与声音能否共同形成生活感，让玩家愿意停留、观察和继续走？
3. 玩家能否自主选择机位与构图，拍到确实在视野中的城市内容，并可靠保存、回看？
4. 浏览器能否承载全市长游，持续加载、释放与恢复，不要求开始前下载整座城市？

每项工作须减少基础还原缺口，或解决上述体验问题。静态截图、标记、对象数量、引擎加载与局部样板均不能单独证明全市目标。

### 1.2 MVP 成立条件

**全市范围、全域环境与景点高还原、连续步行和完整游览闭环必须同时成立。**

用户已明确：还原不是只挑几个地点做得像，而是整个交付范围的基础要求。橘子洲头、五一广场、杜甫江阁、岳麓山直接作为首轮经典场景；它们用于校准并推广制作方法，全市各景点、街巷与沿途环境仍逐处落实要求。无需用户先挑选个人熟悉的少数点，才开始定义全市质量。

允许分批开发和内部验收；只有几个精美地标的技术样板，不作为本 PRD 中的完整 MVP。若资源不足，应调整投入与排期，并明确未完成项。

### 1.3 工作原则：优先探图，再做决策

“探图”采用用户明确提出的斥候比喻：先探索环境，了解资源在哪里、对手在哪里、对手正在发展什么，再决定如何投入和行动。对应到本项目，应先体验现有产品、研究可用资源和制作路径、了解相关产品的当前能力与变化，再形成需求取舍、技术和美术路线、开发优先级。

探图是形成决策前的侦察，适用于产品、体验、美术、数据、技术与制作组织。它不只指搜集长沙地图或景点资料，也不以收集了多少链接、截图或数据条目作为完成证明。

执行顺序：**明确待决问题 → 探图取证 → 比较可行路径 → 记录取舍 → 验证关键未知 → 根据结果更新认识 → 批量投入。**

- 开始一项有明显投入的工作前，先说明它要解决哪一个核心问题，以及哪些外部事实会改变当前决策。
- 亲自使用直接相关的现有产品，观察真实操作与结果。菜单、宣传、静态截图分别标记，不能推定为已验证能力。
- 调查可用地图、模型、像素材质、制作工具与内容管线，记录质量、取得方式、许可、维护成本和限制。已有实现只是候选路径之一。
- 记录参考产品的访问日期、版本线索和正在发展或已经变化的能力；关键条件变化时，重新核对会受影响的决策。
- 证据足以支持下一步取舍后进入行动。剩余未知由有界体验、样板或实验解决，不无限搜集材料，也不凭空宣布结论。
- 用户否定当前效果时，回到原目标和选路依据，撤回已被反证的假设；完成诊断并给出新的具体因果依据后，再继续实现。

此前默认色块灰盒已被用户否定，不能继续把它扩大当作观光成品。2026-10-14完成高度实取与参考实玩，2026-10-15用户明确授权修复高度管线并实施五一广场可玩样板；本版据实际运行结果更新。现有客户端承载这次样板，没有重新生成一张脱离全市的小地图。

本轮修改限高度处理/字段迁移、样板场景、人物/摄影/输入与必要验收。原始OSM、全市道路/水系/建筑轮廓和范围标准保留；局部地面校正与景观近似明确记录。v1.1—v1.4已归档可回溯，不修改用户记忆。代码与玩法验证通过只证明对应能力，不代替还原评审。

### 1.5 探图必须形成的交付物

每次形成或调整重要路线前，更新一份可追溯的探图记录，至少包含：

1. **待决问题**：哪些信息会改变需求、路线、优先级或投入。
2. **现有产品观察**：链接、访问日期或版本线索、实际操作路径、代表场景截图或录像、已观察与未验证能力。
3. **资源与路径调查**：可取得的素材、数据、工具和方法；质量、许可、成本、依赖、限制与已核实的取得方式。
4. **环境与动态**：直接相关产品和方案目前做到什么、正在变化什么，以及变化是否影响本项目。
5. **差距与选择**：现有样机和目标的具体差距；可行方案、取舍理由、剩余未知、下一步验证及通过条件。

探图记录不是链接清单。每条关键结论须能沿“来源或实际体验 → 事实/未知 → 对决策的影响 → 选择与验证”追溯。没有新证据时不重复推翻原目标，也不因当前实现方便而把它预设为正确方案。

每个重要决策单独记录：决策ID、问题、候选方案、足以改变判断的事实、来源与日期/版本、证据级别、质量/取得成本/许可/维护代价、未知、取舍理由、验证与停止条件、负责人、复查触发条件。证据级别区分“本项目实际运行”“亲自体验参考产品”“公开脚本静态核对”“官方资料说明”“推断”“未知”，后两项不能冒充已验证结果。证据足以支持当前动作即停止该项侦察，避免持续研究代替交付。

**本版决定：取消静默300米上限是确定的管线修复要求。** 原始值、规范化值、采用值及其来源/变换分别保留；可疑原值进入资料复核，不得用统一截断冒充校正。性能通过分块、合批和LOD控制，远景简化须保持建筑高度与轮廓。当前楼层×3米及缺值默认6米都属于估计或开发占位，不能因来源标签存在就计为真实还原。2026-10-14只核验并更新需求；2026-10-15已修复管线及迁移现有高度字段，结果见1.9。

修复验收必须重跑上述4个ID的源到生成对照：源值原样可追溯；采用值无静默截断；若与源值不同，有经过审核的校正依据和变换记录；楼层推算/默认占位标签与实取高度分开。再以五一广场标准机位对照核定时期天际线，数据一致性通过不能代替现实高度及画面还原验收。

## 2. 用户与使用场景

| 用户 | 主要动机 | 应获得的体验 |
| --- | --- | --- |
| 熟悉长沙的本地玩家 | 看熟悉的地方如何被做成方块世界 | 不看地名也能辨认地标，走熟悉的街巷，发现可拍照的位置 |
| 对长沙感兴趣的外地玩家 | 轻松了解城市的样貌和景点关系 | 从一处景点自然走向另一处，知道山、江、洲与城区的关系 |
| 喜欢探索与摄影的玩家 | 找机位、等光线、拍城市作品 | 自由构图，切换昼夜，利用路人和城市景观完成照片 |
| 轻度游戏用户 | 无需安装，短时间放松 | 几分钟学会操作，随时退出，回来继续走 |

典型场景：

- **短游 10 分钟**：从五一广场附近开始，穿过老街，走到湘江边，拍一张夜景。
- **周末漫游 30–60 分钟**：在岳麓山一带沿游道行走，参观书院及周边节点，记录一段游览路线。

- **摄影回访**：回到已到访的机位，切换黄昏或夜间，拍摄与上次不同的画面。

以上时长是使用场景示例，不代表对应现实路线一定能在该时间内走完。导航应根据实际路线长度和游戏移动速度计算时间。

## 3. 范围：什么算“全长沙景点”

### 3.1 地理边界

### 3.2 景点纳入规则

“全市景点”不是天然封闭的一个数字。项目建立以下来源的并集，逐项去重、核实，并冻结为 `CS-POI-v1`：

| 来源层 | 必须核对的对象 | 纳入要求 |
| --- | --- | --- |
| A：官方景区 | 截至基准日有效的长沙 A 级旅游景区，以及名录后的新增、变更和撤销公告 | 有效项全部纳入，不只选 4A、5A 或热门景区 |
| B：公共文化 | 官方公开名录或旅游资料中的博物馆、纪念馆、美术馆、名人故居、可参观文保点 | 具备公开游览或文化参观属性的全部登记；与 A 重叠则关联 |
| C：城市游览 | 官方介绍的历史街区、古镇、公园、湿地、山体、江岸游览带、城市标志建筑 | 有明确名称、位置与游览边界的点位或线段纳入 |
| D：补充文旅 | 官方区县旅游线路、乡村旅游与工业旅游资料中的长期游览点，以及用户补充的漏项 | 逐项核实归属、持续性和游览属性，不按热度随意删除 |

私人普通住宅、未开放的设施内部、仅存在于规划中的项目、一次性活动摊位，不直接作为可进入景点。历史遗迹即使现场关闭，也应保留记录并明确可呈现的外围范围；不能因难以制作而从清单消失。

**冻结方法：**以 2026-10-14 为本稿资料基准日；M0 补齐源文件并逐区县核对，记录所有待裁定项。台账冻结后，以确定的集合计算覆盖率。发布前复核新增、撤销和改名；新增项进入变更记录，不通过事后删减未完成项提高覆盖率。

### 3.4 每个景点的最低交付单位

每个景点必须具备：

1. 正确名称、别名、行政归属、位置、来源和资料日期。
2. 真实入口、可走的主要游览路线、核心观景范围；必要的桥、台阶、坡道、平台和碰撞。
3. 全部经核定的核心识别对象；至少一个基础拍摄机位，复杂景点按节点补齐机位。
4. 合理的人流与环境氛围；荒野和纪念性场所不强行配置商贩。
5. 到访记录、景点介绍、照片关联和从公共路网抵达的路线。
6. 对应的还原验收、步行验收、截图和版本记录。

大景区须拆分“景区—子景点—机位”。例如岳麓山景区包含的主要游道和标志节点，应按子项检查，不能只制作入口和一座亭子就视作整个景区完成。父景区与子节点分别统计，避免重复计算总量。

## 4. 世界形态：一座可连续行走的长沙

### 4.1 连续地图规则

- 全市使用一致的地理坐标和尺度，不把宁乡、浏阳挪到主城区旁边。
- 默认按 1 个世界单位对应 1 米组织地理数据；移动速度属于游戏参数，不改变景点间距。
- 在市域内，已核定的公开步行道路、街巷、绿道、桥梁、城镇连接道路及景区游道连续衔接。
- 穿过区县边界、地图分块边界和景区边界时，人物位置、视角、行走和景物关系保持连续；不得出现必须点击“进入下一关”的切换。
- 远郊必须有相应的地形、村落、道路、水系和植被变化，不能用空白平地或重复街道填满距离。
- 河流、山体、铁路、围墙具有真实的通行约束；不能靠穿墙、涉水直走或虚构桥梁补齐路线。
- 现实中确需渡船等方式抵达的地点，逐项记录交通例外；以连续世界中的登船和移动连接，不用瞬移伪装为步行可达。可步行抵达的远郊景点必须保留完整步行路线。
- 地图外设置与地理边界一致的自然边界和提示；不把未制作的市域内区域伪装成地图边缘。

### 4.2 全域制作精度

| 层级 | 范围 | 制作要求 |
| --- | --- | --- |
| 全域地理底图 | 整个长沙市域 | 地形、水系、道路、城镇位置、主要建筑体量及植被分布有数据依据；形成可持续行走的世界 |
| 日常街巷与郊野 | 全市已核定可游览区域及连接，包含城区、城郊、远郊 | 真实路网/街宽、转向、体量层次、建筑类型、立面与屋顶特征、植被/用地变化有依据；原创模块可复用，须校正区域差异 |
| 景点游览范围 | 全量台账中每个景点 | 手工校正建筑、地形、主要游线、环境陈设与全部核心识别节点 |
| 主要摄影范围 | 标准机位、近景细节、核心天际线 | 优先保证构图、轮廓、材质、牌匾与光照；不得用远景简模替代近景验收 |

高还原要求覆盖全域；细节预算依据观看距离和内容类型安排，所有景点仍通过同一最低还原门槛，城市环境按8.6验收。低细节远景保留真实地形、体量、天际线和区域差异；进入近景后有相应立面、铺装与街景内容。模块化用于生产复用，不能把老城、现代街区、乡镇和山野生成同一种模板。普通背景不承诺逐户内部复刻；核心景点内部按第7节制作。

### 4.3 长途探索的产品支持

- 导航显示真实路线距离、按当前移动速度估算的时间、途中地标和休息节点。
- 提供可暂停的持续前行；前方碰撞、道路缺失、未加载地面或危险落差时停止。
- 长途进度可随时保存，下次从安全位置继续；不要求一次坐完数小时。
- 新建游览可选择任一已发布景点作为起点，便于玩家直接参观；这不作为连续世界的验收方法。
- 快捷旅行和交通工具可在后续增加，但不得替代全域道路制作和连续步行能力。

## 6. 核心玩法与页面结构

### 6.1 核心循环

**选择起点 → 自由行走 → 遇见景点和路人 → 找到机位 → 拍照 → 保存照片与游览记录 → 继续走向下一处。**

游览没有体力惩罚、强制战斗、资源收集门槛或关卡锁。玩家不必完成任务才能看景点。轻量摄影主题和游览护照用于提供方向，不强迫清空清单。

### 6.2 首次体验

1. 打开首页，看到真实游戏画面、产品名称、“开始游览”和“继续游览”。
2. 默认从五一广场的核定安全公共空间进入；可直接选橘子洲头、杜甫江阁、岳麓山等经典起点，也可在地图另选已交付起点。各起点入口、出生机位和首个拍摄位置须核定，首屏表达相应真实场景。
3. 首屏只引导移动、转动视角和打开相机，约 60 秒内可完成。
4. 导览给出一条短途步行建议，同时允许自由离开路线。
5. 玩家完成第一张照片后看到相册入口和继续游览提示。

### 6.3 信息架构

| 页面或面板 | 主要内容 | 关键动作 |
| --- | --- | --- |
| 首页 | 城市预览、开始、继续、画质与操作提示 | 进入世界 |

| 拍照模式 | 干净画面、构图线、焦距感、姿势、时间与人群选项 | 拍摄、预览、保存 |

MVP 不要求注册账号。首次加载、截图失败、存储不足和网络中断均提供明确状态，不能让玩家面对长期无反馈的黑屏。

### 6.4 完整游览体验

全市高还原之上，行走、路人和摄影须彼此衔接。场景在行进中呈现近中远景变化，真实路口、导览、地标视线和导航帮助判断下一步；玩家可自由停留、改变方向、交谈或取景。拍摄与到访形成可回看的城市记录，再继续原路或前往下一处，不以清任务或货币消耗作为看景门槛。

初始游览以四大经典场景展示城区广场、江洲、临江古建和山地差异；长途则保留真实聚落、水系、农田/林地与城郊变化，结合分段导航和可恢复进度。热闹与安静依据地点、时段和资料设计，不在每段路上强塞同样人群或互动。

以实际玩家行为评估是否顺畅、愿意停留和继续探索；景点识别、点击拍照、NPC数量和到访计数各自只是局部证据。

## 7. 功能需求

### F01：连续世界与场景加载 · P0

- 在同一世界中展示全域地形与城市，按人物位置和观察方向分块加载。
- 当前行走区域的地面和碰撞须先于可视细节就绪；不得让玩家走入空洞。
- 预取前方道路、相邻分块和远处主要地标；已远离的资源应释放或进入受限缓存。
- 摄影模式按实际视野准备高质量资源；未就绪时显示短暂准备状态，不能把缺失资源拍成“成功照片”。
- 网络不足时，保留已加载区域的行走与拍照；到未加载边缘前安全停止，说明原因并自动恢复预取。该异常不算正常连续性验收通过。

### F02：角色移动与观察 · P0

| 操作 | 默认键位或交互 |
| --- | --- |
| 行走 | W/A/S/D 或方向键 |
| 转动视角 | 鼠标；支持指针锁定，并说明如何释放 |
| 快走 | Shift；无体力条 |
| 小幅跳跃 | 空格；用于一般路缘，不可翻越建筑和封闭边界 |
| 交互 | E |
| 第一/第三人称 | V |
| 相机 | C |
| 地图 | M |
| 暂停或关闭面板 | Esc，按浏览器指针锁定状态合理处理 |

- 建议初始步行速度 3 m/s、快走 5.5 m/s，作为可调游戏参数，在样板中验证舒适度；不作为现实步行速度宣传。
- 支持台阶、坡道、桥梁、室内门洞；相机遇墙缩进，避免穿模。
- 玩家跌入异常地形可回到最近安全位置，保留已取得照片和到访记录。
- 行走镜头默认无明显摇晃；提供灵敏度、视野角和镜头晃动开关。
- 角色有清楚的面部、发型、衣服和鞋子分区及统一像素材质；站姿、步态、转向和摄影姿态协调，不以无细节体块作为最终人物。镜头、动作与实际移动速度一起验证。

### F03：地图、搜索与步行导航 · P0

- 全市地图支持缩放、拖动，显示当前位置和地图比例。
- 按区县、景点类型、到访状态筛选；正式名称、旧名、常用别名均可搜索。
- 步行导航基于实际路网和游道，识别桥梁、台阶、阻隔和公开出入口。
- 路线在地图和世界中对应同一条路径；不可把汽车道路距离直接作为可步行路径。
- 长路线分段列出途经区域、里程和可保存节点，支持中途修改目的地。
- 无可核实路径时显示原因与待核查状态；不得生成穿山、跨水或穿封闭院落的直线。
- 所有正常步行可达景点必须接入共同路网。交通例外点独立登记并验证连续交通连接。

### F04：摄影与导出 · P0

- 随时进入拍照模式，隐藏游戏HUD，可开启三分线。进入摄影/相册后必须能操作按钮与滑块；世界指针锁定和自由光标切换有明确方式，不能让画布抢走控件点击或误触快门。
- 文本输入时字母用于输入，Esc能返回；按钮/变焦滑块焦点下摄影快捷键及退出有明确规则，C或Esc按界面说明工作。从已锁定和未锁定世界视角进入均须验证。
- 提供第一人称风景照、第三人称合照两种模式；第三人称提供站立、挥手、比心等少量原创动作。
- 相机可在人物附近有限移动与转动，不能借摄影模式穿墙、穿越未加载区域或跨越大段距离。
- 支持水平旋转、俯仰、视野角调整，预设横图 16:9、方图 1:1、竖图 9:16；提供 3 秒倒计时。
- 支持当前时间、黄昏、夜晚等光照预设；拍摄完成后恢复拍照前的游览时间设置。
- “保留路人/隐藏路人”只控制照片表现；不改变已到访、导航或其他进度。
- 默认导出 1920×1080 PNG；其余比例保留相当像素量。首版不要求 4K。
- 拍摄时锁定瞬间的角色、NPC 与光照状态，资源准备完成后再输出该状态的图像。
- 可选生成“方块长沙 · 景点名”纪念文字，默认保留一份不带文字的原图。
- 拍摄预览、保存到相册、下载到设备分别给出结果；下载被浏览器拦截时可手动重试。
- 所有拍摄素材需满足浏览器截图的跨域要求；黑图、错误贴图、空白 PNG 均视为失败。
- 景点关联以拍摄瞬间视野、可见主体及遮挡为依据，不能只因人物在景点附近便认定拍到。未确认地标的照片照常作为普通风景保存；不强制关联、不误解锁记录。可采用确定性的空间/可见性判断，需验证无遮挡、遮挡、画面外和多景同框。

### F05：相册与本地保存 · P0

- 相册展示缩略图、地点、游戏时间、创建时间、相机参数和内容版本。
- 按景点与日期筛选；可逐张下载、删除，删除前有明确确认。
- 照片使用本地持久化存储，首次保存时提示“保存在当前浏览器，建议下载留存”。
- 默认保留上限 100 张，同时受实际存储空间约束；不能静默覆盖旧照片。
- 存储不足时允许直接下载新照片，保留旧照片，并引导清理。
- 本地保存被禁用时明确提示，仍提供当次下载；不得显示“已保存”后丢失照片。

### F06：路人和城市生活 · P0

NPC 采用可控脚本和行为状态，首版不依赖在线大模型。重点是路人看起来在生活，而不是所有人围着玩家说话。

| 类型 | 基础行为 | 场景与互动 |
| --- | --- | --- |
| 普通市民 | 散步、停留、看景、坐下 | 城区与公园，简短招呼 |
| 游客 | 看导览、拍照、结伴停留 | 景点和街区，提供附近看点提示 |
| 商贩与店员 | 招呼、整理物品、服务 | 合适的商业街，介绍地方食物与街区 |
| 讲解员与工作人员 | 定点讲解、指路、维持场景秩序 | 博物馆、纪念馆与景区入口 |
| 学生、跑者等场景角色 | 经过、阅读、慢跑 | 校园周边、滨水绿道等对应场景 |

- 至少具备行走、避障、停留、看景或拍照、交谈五类行为，按场景组合。
- 城市街区、公园、山地和纪念场所采用不同密度与行为；夜间相应变化。
- 标准画质初始预算为视野及近邻最多 40 个完整行为 NPC，密集场景可达 60 个；低画质仍保留 12 个附近角色的容量。具体数量须在样板中实测，不能全量关掉路人以通过性能门槛。
- 不把容量下限强行用在无人山野；每个场景单独配置符合环境的人流基线。
- 玩家附近不突然生成、消失或换装；路人避免长期原地互撞、穿墙和堵住关键道路。
- 配置多套外观和动作，降低近距离重复；白天与夜间有一致的人物行为规则。
- 对话以两至三层短选项为主，如“这里有什么看点”“附近怎么走”；回答绑定核实过的景点资料。
- 长沙话作为少量经本地审核的氛围表达，并提供普通话字幕；不要求全量方言配音。
- NPC可被拍进照片，正常站位或短暂停留即可同框，不要求复杂自由摆位或任意动作指挥。
- 看点、指路和摄影提示绑定当前地点及核实资料，按时间/场所使用适合语境；交谈时可短暂停步面向玩家，结束后恢复活动。同一套话不跨场景硬套，未知路径不编造。

### F07：景点介绍与核心室内 · P0

- 每个景点提供约 80–150 字概述、三条以内看点、资料日期和来源入口。
- 文案区分历史建筑、重建建筑、考古遗址、现代仿古文旅项目，不能混称。
- 景区内主要开放游览区域和核心识别节点应可走近；需要进院、入馆、入洞才能获得主要游览价值的，须制作对应的核心空间与动线。
- 博物馆首版制作经内容方案核定的代表展陈和主要参观空间；不宣称复刻全部馆藏和所有展厅。所有核心室内范围在 M0 按景点登记，不在制作结束后缩小。
- 未复刻的普通商铺、管理用房和非开放区域设合理边界，不用完全相同的空房间充数。
- 现实营业时间、预约与票务如展示，必须带核实日期和官方链接；不与游戏中的全天游览规则混淆。

### F08：昼夜、环境和声音 · P0

- 至少具备白天、黄昏、夜晚三种完整光照状态；玩家可暂停自然流逝并选择时间。
- 夜间建筑照明、路灯、江面反光和人流同步变化，关键路线保持可辨认。
- 城市、老街、江岸、寺院、山林具有不同的环境音；支持独立调节音乐和环境音。
- 含夜景的景点必须逐点验收，不能仅把天空调黑。
- MVP 采用一套明确的季节基准。杜鹃、樱花等季节看点如采用专题表现，应标明季节，避免宣称实时季节模拟。
- 首版不要求动态天气、全年四季、真实节假日客流和实时城市事件。

### F09：游览护照与轻量引导 · P0

- 到达核定游览区域并停留约 10 秒可记录到访；仅从远处路过或在地图上点击不算到访。
- 摄影完成单独记录，不强制拍照才承认到访；照片拍摄与手动存储失败分别处理。
- 按区县展示已到访数与当前版本总数，景区与子节点分开展示。
- 提供老城漫步、山水洲城、艺术建筑、古镇与远郊等主题线路，但允许自由组合。
- 轻量摄影主题如“拍一张有湘江和地标的照片”；首版用机位、视角范围和可见对象检查，不依赖未经验证的图像评分。
- 隐藏路人、切换时间和直接选择新起点不影响自由游览；相关记录保留真实使用方式。

### F10：存档与恢复 · P0

- 自动保存当前位置、视角、到访记录、选中路线、时间设置与偏好；关键动作后即时保存，移动中约每30秒保存。相册、任务恢复与场景时间/视角恢复分别验证，不因前者成功便推定后者通过。
- 刷新或重新打开网页后可以继续；地图更新导致原位置失效时，回到最近安全节点并说明。
- 长途探索保存实际已走路线和中断位置，不能因跨区县加载重置。
- 提供本地进度备份与恢复；进度包不默认包含照片，照片须另行下载。
- 不主动清除旧存档；数据版本迁移失败应保留原数据并给出恢复方式。

### F11：浏览器与辅助设置 · P0

- 桌面版支持键鼠，目标分辨率 1366×768 至 2560×1440；中文为首发语言。
- 发布时锁定 Windows 上 Chrome、Edge 的实际验收版本；其他浏览器按验证结果说明支持状态。
- 基础渲染能力不满足时给出可理解的说明；高级图形能力作为增强，不作为进入游戏的唯一条件。
- 提供低、中、高画质与自动建议；降低阴影、反射、远景细节，仍保留核心景点识别和路人。
- 设置面板支持键盘操作、字幕、界面字号和降低镜头动态效果。

| P0：完整 MVP 必须包含 | P1：可在首版后增加 | P2：远期方向 |

## 8. 美术标准：方块风格下的高度还原

### 8.1 风格原则

- 建筑、地形与人物使用一致的方块语言和原创像素材质。
- 先保留真实轮廓、比例和空间关系，再做像素化；不能把所有景点变成同一种方盒子。
- 建筑主体、雕塑、古建屋顶、曲面艺术建筑允许采用不同细分尺度；细分程度由识别效果和性能共同决定。
- 重要牌匾与地名保证可读，颜色、位置、字形有参考；普通商业招牌按资料与素材许可处理。
- 青年毛泽东艺术雕塑、寺院、纪念馆等内容单独审校，避免夸张变形、戏谑动作和错误文化细节。
- 真实性主要来自可观察的城市特征；增加泛用中国风道具不能替代长沙细节。

### 8.2 六项还原评分

以下为拟定的产品验收标准，须用样板校准评分说明；全量制作后不能因不达标而降低门槛。

| 维度 | 权重 | 检查内容 |
| --- | --- | --- |
| 轮廓与体量 | 25 | 建筑层数、屋顶、雕塑姿态、建筑群组合、主要高宽比例 |
| 空间与地理关系 | 25 | 入口、朝向、道路、地形、水岸、周边建筑、跨江视线 |
| 标志性细节 | 20 | 牌匾、立柱、飞檐、门窗、台阶、围墙、代表展陈与节点 |
| 颜色与材质 | 10 | 墙体、瓦、石、金属、水面和植物的主色与质感 |
| 环境与氛围 | 10 | 植被、街具、灯光、声音、场所合适的人群 |
| 摄影一致性 | 10 | 标准取景点能否还原参考构图与前中后景关系 |

**逐景通过线：**总分不低于 85/100；轮廓、空间、标志细节分别达到该项满分的 80%；关键事实错误为零。不得用全市平均分掩盖个别景点不合格。

关键事实错误包括：景点放错位置或行政区域、建筑/雕塑主体错误、核心节点遗漏、重要牌匾错误、遗址与仿古园区混淆、跨江景物方向颠倒、必须游览的入口无法通过。

### 8.3 几何与画面对照

- 有可靠测绘或尺寸资料的对象：核心高宽比建议误差不超过 10%，主要入口和平面关键控制点建议平面偏差不超过 5 米。
- 没有可靠尺寸的对象：使用多个方向的照片和地图交叉校准，标记估算置信度；无法证实精度时，不出具“米级误差通过”的结论。
- 每个普通景点至少记录三个方向的参考；复杂景区按子节点补齐，不能只对照一张正面照。
- 每景至少保存入口、代表机位、主要游线的游戏截图；有夜景内容的增加夜间对照。
- 植被和路人的随机分布可变化；地标轮廓、地理关系与核心识别细节不得随机变化。

### 8.4 无真人的实景、几何与独立视觉复核

用户已明确禁止安排真人。本项目不招募、邀请或组织真人盲辨、访谈和体验测试，也不以真人样本作为交付前置；2026-10-15的真人评审页已取消收集。不得让模型扮演熟悉长沙的居民填写问卷，或把模型判断计作真人识别率。

1. 每处场所建立可检查的“参考事实—制作对象—运行画面”对照表。记录来源、发布/拍摄日期、身份、相对地面高度、参考机位、构建哈希；测量、已建记录、设计规格、按层推导和照片估计分开，不以来源数量投票决定真实值。
2. 优先使用有尺寸/坐标依据的对象验证高宽比、控制点、朝向和相互遮挡；按8.3记录误差及计算方法。无可靠尺寸或相机标定的项只能给出估计/视觉差异，不填写测量通过。
3. 按8.2六维在制作前冻结逐项检查表、权重与参考依据。缺证项计未验证，不能删除分母或用其他项加分补齐；评分需逐项附证，85分、前三项各80%、关键错误零的门槛保持。核心节点遗漏或错误直接退回。
4. 至少保存入口、主要游线和三个方向的游戏原图及对应真实参考，记录相机高度、方向、视野、时段及位置估计。去掉名称/地图提示后由未参与该资产制作的独立模型辅助检查轮廓、比例、节点、材质和遮挡差异；模型意见须回到原始照片核对，不能单独证明事实或代替几何测量。
5. 每条差异包含证据位置、受影响对象、修正决定、代码/资产变更及同机位复验。保留反对意见和误判的处理依据，不能仅凭开发者自称相似或模型总分结案。
6. 视觉、几何、操作和性能分别给出通过/未通过/未验证。实际操作按11.2留存键鼠动作、照片原件、恢复及路人回执；功能通过不能抵消还原失败。真人识别、偏好和留存无样本时记未测，不阻塞已替换的验收机制，也不冒称已证实。

### 8.5 参考对标与实际画面验收

M1按5.2类型矩阵校准视觉完成度基线，覆盖密集街区、古建山地、复杂建筑/雕塑、核心室内、江岸桥梁、远郊过渡。每类提供真实长沙资料、参考产品的已观察画面和本游戏实际运行画面，记录差异与取舍。本游戏与真实长沙尽量匹配机位、视角、距离和时段；不同城市参考比较相近尺度和用途的制作完成度，不假称能使用同一地理机位。

以下内容逐项评审并留证：

| 检查项 | 通过依据 | 对应验收 |
| --- | --- | --- |
| 首屏与地标识别 | 起点、镜头、近景共同表达长沙；真实资料支持身份，无需标签也能辨认 | 8.2轮廓/空间/细节及8.4去提示视觉复核 |
| 建筑与像素材质 | 轮廓、层数、门窗、屋顶、标识和材料有对应制作；像素密度一致，无大片无内容的默认色块 | 8.2轮廓/细节/颜色材质，记录像素密度、距离及画质 |
| 街景与角色 | 人行空间、植被、街具、人群符合地点，动作、接触阴影与地面关系正确 | 8.2空间/环境氛围及AC10实察 |
| 摄影体验 | 可移动转向与构图，近中远景、昼夜、预览、保存导出连贯，使用实际游戏画面 | 8.2摄影一致性、AC11/12及11.2实际摄影操作验证 |
| 内容与工程共同成立 | 以上画面标准下仍满足实机/网络的行走与摄影要求 | 第10节性能及AC16，工程通过不替代画面评审 |

样板未通过时，先找出资产、资料、渲染或路线选择的原因，修改并复验；不能增加标签、灰盒或测试数量来推动美术验收。M1基线保存构建、资料/资产版本、设备、画质、机位、逐项评分及实景/几何复核结果，列出与参考的差异和处理决定；不能只由团队自评“像了”定标。8.2的85分、分项线和8.4无真人证据要求保留。基线通过前不进入依赖它的全市批量精制；独立数据核对可继续，不据此宣称体验阶段完成。

### 8.6 全市城市环境的基础验收

除逐景第8.2—8.4节验收外，按城区街区、城郊聚落、远郊地貌及相应地理分块建立城市环境验收单元，覆盖完整交付市域。每单元记录边界、资料时期/来源、形态与材质规则、制作状态、运行观察证据、问题及复验。代表样板校准方法，不能把一处通过推定成其他单元通过；缺证单元记“未验证”。

| 检查项 | 基础通过要求 |
| --- | --- |
| 地理和空间 | 地形、水系、道路转向/宽窄、公开连接和城市分布有依据；与相邻单元连续，无虚构路口、穿水捷径或错误山江方向 |
| 建筑体量与区域差异 | 高度层次、密度、建筑类型、屋顶及重要立面符合参考；来源明确，测量/推导/估计/占位分开。开发默认体量不直接算最终还原，估计值须结合参考校准 |
| 近景完成度 | 实际可走区域有相应地面、材质、门窗/标识、街具与植物细节；远景简化保持身份与天际线，近景不沿用无内容默认色块 |
| 连续城市与郊野 | 老城、现代城区、乡镇、农田/林地和山水有真实疏密、结构及过渡；不能跨区域铺同一通用街道或空白底板 |
| 人物与氛围 | 角色、路人行为、人流、光照与环境声音符合场所和时段；安静区域保留安静，热闹区域有依据，通路与机位不长期堵塞 |
| 游览与摄影 | 实际可行走、停留、取景、保存及恢复，场景细节和可见关系能进入照片；同一画质下满足性能要求 |

单元须逐项满足且关键事实错误为零；影响体量、区域特征、通行或照片内容的缺口未闭合时不通过。全域制作/验收台账随发布交付，覆盖单元与未验证项可核对。单元通过不能替代其内部景点的85分与实景/几何验收，景点通过也不能替代周边城市环境验收。

### 9.2 生产流程

**探图与路线决策 → 资料核对 → 地理定位 → 代表场景与质量基线 → 灰盒与路网 → 景点模型 → 材质与环境 → 游线和碰撞 → NPC → 标准机位 → 还原评审 → 性能验证 → 版本入库。**

- 灰盒阶段先核对尺度、入口和前往下一景点的路径，避免美术完成后发现地点与道路不一致。
- 复用古建、街具、植被等模块；地标主体与核心识别对象必须有独立校正。
- 自动生成用于地理底层和普通背景，人工负责识别度与可游览质量。生成高度、默认形态和原始资料分开标记；缺失细节不能因生成成功变成“已还原”。
- 高度管线按1.6.2修复静默300米截断，保留原始标签/单位、规范化米值、采用高度、出处、公式或审核校正依据；源异常标记复核，不能靠固定上限掩盖。资料版本变化后比较受影响建筑与天际线；LOD减少几何细节，不能缩短建筑。
- M1先在城区与远郊各取得一组可用资料，走通来源核验、实际取得、导入、校正到可行走/拍照场景；记录工时、缺项、许可、资源体量和返工。官方介绍只是候选依据。
- 通用街具、植被、背景模块可复用，但统一尺度、像素密度与色彩；长沙主体、立面、牌匾、游线和机位逐处校正。普通长路保留真实低密度，不虚构地标或随机堆NPC；导航、真实聚落与存档提供方向和延续感。
- 每批资产与地图版本绑定；修改核心对象后，重验受影响机位和路径。

## 10. 技术约束与性能目标

本节定义必须具备的能力，不预设未验证的引擎。具体 Web 3D 引擎、资产格式与地理工具在M1依样板结果确定。资源采用状态以1.6/1.7为准，已被实际取数否定的批量补高路线不能继续作为默认方案；对比用同一核定区域、资料和验收口径，记录清理工时、几何/纹理体量、质量、碰撞和性能。只测会影响D02/D03的关键差异；不因工具新颖重写，也不因已有代码拒绝更合适的路径。

### 10.1 必须满足的实现能力

- 大范围坐标管理：地理坐标保留在数据层，渲染使用局部坐标或原点重定位，避免远离城区后抖动与碰撞失准。
- 空间分块与多级细节：城市不是逐个方块常驻内存；按块、批次和视距组织网格、碰撞、NPC 与资源。
- 近中远景独立预算：近景可走、可看、可拍；远景保持正确天际线与地形，不要求持续全精度。
- 路网与可走表面一致：地图导航、世界碰撞、台阶桥梁和实际入口来源一致。
- 异步资源与缓存：加载、解码和场景准备不能频繁阻塞行走；版本更新可以使过期缓存失效。
- 内容部署可追踪：发布包能追溯地图、POI、模型、文案与验收版本；回退不能损坏已有相册和进度。

| 指标 | 初始验收目标 | 口径 |

## 11. 产品指标与验证方法

### 11.1 发布门槛：缺一项即未完成

| 指标 | 门槛 |
| --- | --- |
| 全量景点覆盖 | `验收通过的父级 POI 数 / CS-POI-v1 应交付父级 POI 数 = 100%`；核心子节点单独达到 100% |
| 九区县覆盖 | 每个区县的全部应交付项均通过，不能以全市平均覆盖率代替 |
| 连续世界 | 全域数据分块齐备；所有正常步行可达 POI 接入共同路网，交通例外逐项闭合 |
| 景点还原 | 每景达到第8.2—8.5节门槛，关键错误为零；未测景点不计为通过 |
| 全域城市环境 | 按8.6建立并覆盖全域验收单元，城区/城郊/远郊基础质量均通过，未验证与未完成单元为零；不能只以景点或道路连通替代 |
| 画面与游览完成度 | 按8.5逐项提供实际运行证据，达到M1校准基线；关键机位、材质、近景、角色和摄影体验均完成评审 |
| 核心功能 | 行走、NPC、地图、相机、相册、昼夜、存档全部通过验收 |
| 性能与稳定 | 达到 M1 固定的实机、网络与场景验收目标；剩余偏差须显式评审 |

覆盖分母、资料日期、版本和去重规则随验收报告一起输出。若 `CS-POI-v1` 尚未核定，则“全市景点覆盖率”记为未完成，不能填写 100%。

### 11.2 无真人的操作验证与产品假设边界

遵守用户禁止安排真人的要求，原20人体验测试和熟悉者评分/自主拍照比例不再作为交付前置。操作验收使用真实浏览器、实际键鼠、真实渲染/存储/下载回执，不在测试中直接写入成功状态。用于碰撞或特定机位的定位夹具必须显式标注，与正常连续行走分列。

| 问题 | 当前验收依据 | 结论边界 |
| --- | --- | --- |
| 操作流程能否完成 | 从新旅程起步，用实际控件完成移动、地图、相机、保存和下载；覆盖焦点、输入锁定及退出，并留失败回执 | 证明脚本对应流程可完成，不证明90%新玩家无需帮助 |
| 是否还原长沙 | 8.2/8.3/8.4逐景参考事实、几何误差、去提示画面对照和独立视觉差异复核 | 不填真人识别率或居民满意度；未知尺寸保持未验证 |
| 摄影是否正确 | 日夜、风景/合照、三个画幅、路人开关；逐一核对预览/原件、无HUD、尺寸与内容，并自然重开复验 | 证明摄影功能与内容正确，不证明玩家会主动拍照 |
| 城市能否继续游览 | 按AC02—AC06实际行走/拓扑/加载/存档分别留证，明确实时走与加速模拟、代表路线与全量路线 | 不以路线可走推断玩家愿意继续走 |
| 路人是否正确运行 | 按AC10真实时间、各场景采样，记录角色身份、路径、位置、行为、相交/堵塞和对话；绑定代码/数据版本 | 有限采样无错误不等于所有时刻无错误，更不证明主观生活感 |

摄影吸引力、自主探索意愿、生活感满意度与长期留存仍是未测产品假设。不得把自动化拍摄次数、脚本行走长度或模型偏好替换成真人行为结果；本项目也不因此另行安排真人测试。发布时如有自然产生的合法统计，应单独说明样本与口径，不自动恢复已取消的招募路线。

### 11.3 最小事件记录

记录开始/继续游览、场景与分块加载失败、步行段完成、景点到访、NPC 交互、相机打开、拍摄成功/失败、本地保存成功/失败、照片下载触发、存档恢复、异常退出。

通过实际存储回执判断“已保存”，不能把点击按钮计为保存成功；浏览器通常无法确认用户最终文件落盘时，下载事件标注为“已触发下载”。默认不上传照片内容，不采集真实世界位置；公开部署时明确告知必要统计范围。

## 13. 交付阶段与门槛

### M-1：探图与策略决策

产出：1.4/1.5可复核参考体验、1.4.1静态核对，1.6产品/资源现状、样机差距，1.7决策与未知，5.2样板矩阵及M1基线草案。静态代码、官方说明、亲自实玩、已接入运行分别记录；明确哪些证据能影响选择。

门槛：1.5逐项记录足以支持下一步选择，能力与未知清楚，能说明下一动作如何改善“像长沙、可游览、值得拍照”。对影响首屏、NPC、摄影的参考能力逐项尝试，不能只看首页/菜单判定闭环；缺证保留对应未知。资源须核实具体取得方式与许可，再进入M1取得/导入样板。灰盒与未验证方案不是默认答案；不以参考数量结案，不要求穷尽未知，剩余问题带通过条件进入样板。

### M0：全量范围与资料就绪

产出：`CS-POI-v1`、九区县核对表、行政与全域地理数据方案、逐景核心游览范围、全域环境单元/资料缺口、建筑高度与形态来源候选、资料/权属清单、待裁定事项及初步资源预算。

门槛：没有未裁定的景点纳入项；每个点有明确边界和制作单元；能说明全市底图与路网的取得方式。名单或关键地理资料未闭合时，可以继续不依赖它的设计工作，但不能宣称完成全量估算。

### M1：真实体验和技术可行性样板

产出：以橘子洲头、五一广场、杜甫江阁、岳麓山开始校准，按5.2补足复杂建筑、老街、室内、桥梁及城郊/远郊类型；城区与远郊资料到运行画面的管线，采用1.6.1高度源实取结论及1.6.2加工缺陷结论，以1.9已完成的高度修复/回归为基线，不再按Overture补高假设制作；真实资料/参考对标、四大经典起点验证、材质/街道/角色/NPC/日夜摄影；连续实走/恢复，性能、体量、制作及返工工时。样板决定全市制作方法，不替代全市交付。

门槛：样板按8.2/8.4/8.5及8.6相应要求通过，人物、行走、摄影与生活感共同成立；同画质下性能/流式加载可持续；D02/D03/D07有证据支持，D04各起点有核实机位和游览接入，估算含资料取得与返工。不能凭单测、灰盒或路由结案；失败追查资料、资产、管线或载体，不缩小地图或降低标准。

### M2：全市连续底图与全量灰盒

产出：完整市域地形、水系、道路、普通背景、全部景点灰盒、入口、游线、跨区县连接、导航及存档；按8.6登记全域单元，区分实际资料、估计、占位与尚待精制内容。

门槛：所有应交付景点已定位并可到达；全域分块完整；路网与地面、碰撞一致。此时尚不宣称完成高还原 MVP。

### M3：全市景点制作与逐批验收

产出：全量精制景点、城市街区/城郊/远郊环境、核心室内、机位、NPC、音效、介绍、昼夜、相册与游览护照。

门槛：每批逐景按相同还原标准、城市环境按8.6验收；所有区县推进，远郊不能永久后置，样板或经典景点完成不替代其他内容。剩余任务及返工有明确负责人。

### M4：完整 MVP 验收与发布准备

产出：全量覆盖审计、连续长游记录、无真人实际操作回执、逐景还原证据、性能报告、已知问题、部署与回退方案、最终交付清单。

门槛：第 11 节发布门槛闭合，P0 验收全部完成；实景、操作或性能未达标的，明确修复和复验安排；不以取消真人测试判定视觉通过。公开部署与后续运营另行执行发布决策。

### 13.1 排期与预算方法

这是**功能收敛、内容全域覆盖的首版**，地图与资产工作量较大。未取得全量清单和样板工时之前，不承诺几周完成或给出精确报价。

建议初始角色配置：产品/内容 1 人、客户端与世界系统 2–3 人、技术美术 1 人、场景美术 2–4 人、测试与资料核查 1–2 人；可兼职或调整，但职责不能缺失。

预算以三部分核算：

1. **公共系统与全域底图**：引擎接入、地图、导航、角色、流式加载、摄影、NPC、存档和构建部署。
2. **内容制作**：按普通建筑、复杂地标、古镇街区、自然景区、核心室内分类，以“单元数 × 样板实测工时”计算，并加入已观测返工量。
3. **验证与运行**：全量名录核对、实地/影像资料、授权素材、性能设备、逐景评审、长途验收、存储与流量。

M1 后依据有效并行人数和依赖关系排期，不能把人数简单相除当成总工期。每个阶段记录它减少了哪项核心不确定性或完成了哪部分应交付内容。

## 14. 主要风险与应对

| 风险 | 对产品的实际影响 | 应对与决策依据 |
| --- | --- | --- |
| 闭门选路线、缺少外部体验依据 | 工程能运行，但场景不像长沙，整体完成度与现有产品差距大 | M-1先探图并记录取舍；M1实际画面和游览门槛通过后再批量制作 |
| 景点清单遗漏或来源过时 | 宣称全市覆盖却缺少区县或新景点 | M0 合并名录与变更公告，逐区核对，发布前复核；保留历史版本 |
| 只建景点，城市之间空白 | 无法一路走到远郊 | 全域底图独立交付，M2 与 AC06 检查全部分块，景点路段不能代替全域 |
| 方块化损失地标特征 | 看起来是通用城市 | 复杂形态先做样板，允许细分尺度与专用网格，逐景去提示实景/几何复核和对照 |
| 真实路网缺少可走信息 | 导航穿墙、跨河、走上不适合步行的道路 | 核对公开出入口与人行连接，逐条记录例外，不伪造捷径 |
| 浏览器内存、加载与长距离精度 | 越走越卡、远郊抖动、穿地 | 分块、资源预算、局部坐标和实机长游；以具体失败记录修复 |
| 全域内容工时被低估 | 样板好看但全市迟迟不完成 | 用全量制作单元和实测工时预算；优先复用普通背景模块，保留景点门槛 |
| 室内和展品资料不足 | 进馆后体验空洞或内容错误 | 提前核定核心空间，补齐资料与使用依据，缺口作为公开任务保留 |
| 长距离行走时间过长 | 玩家中途放弃 | 清楚显示时间、可暂停前行、沿途节点与可靠存档；保留连续步行目标 |
| NPC 机械或妨碍游览 | 城市虽有人却更不自然 | 分场景配置、行为组合与路口避障；以观察评审验证，不堆数量 |
| 城市改造和资料混期 | 场景事实相互冲突 | 按参考日期制作，保留改名与改造记录，有计划地更新 |
