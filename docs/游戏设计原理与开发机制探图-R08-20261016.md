## 新发现、撤回判断与制作决定

以下是项目推论，不代表理论已证明长沙游戏好玩。

| 新发现 | 撤回的判断 | 项目采用的决定与边界 |
| --- | --- | --- |
| Cook把玩家决策、动作、模拟、反馈、更新理解连在一起 | 行走→摄影→完成任务串通即可代表探索成立 | 分清保存原件、识别主体、完成看点；关注观察/选机位/再尝试，例如移动后让被遮挡双塔同框。不能从操作日志直接读出理解，不能把一切乐趣归为学习。 |
| Hodent区分知觉、注意、记忆和可供性；手感案例曾由大小/速度归因改为绕障碍瞬间转向 | HUD位置、字体、说明完成就等于清楚；手感差等于速度或FPS | 核对信息一致、提示时机与实践机会，入口/楼梯外形和实际通行预期。没有据此判定某个长沙入口有缺陷，作者示例数字不直接变成统一标准。 |
| SDT原文区分反馈性奖励与控制；批评研究指出理论套用问题 | 奖励/任务/选择越多越好，或奖励都应删除 | 保留自选目标和任务栏，不能凭理论增删模块或指定类型。禁止真人保持，AI/自动化不能生成主观量表分数；真人多人关系感证据不直接移植为NPC已有效。 |
| 日常、停留、自愿参与和可退出也值得设计 | 每段路都要活动、每个路人都要派事 | 真实尺度长路不能靠重复任务填满，路人目的/停留/反应有独立价值；40人都动不代表生活感。不能为气氛任意改变真实空间。 |
| 内容架构包含标准、组合、依赖、成本及晚期修订 | 拆src或做漂亮样板就能生产全长沙 | 关联事实/空间/资产/通行/人物/摄影，修改时追踪碰撞/机位/路径/导航。复用街具不替代真实商铺，曲面庭院不服从矩形模板，高度冲突不能为生成便利消除。工具先用于真实变更，不先建通用编辑器/换引擎。 |
| 可玩检查场景应共用正式资源和行为，仍需真实游戏检查 | 反复长途到测试点或静态角色排队图是唯一方法 | 重复转向/碰撞/材质/角色问题可用共用控制器和摄影的场景比较；仍须回到五一广场与全市验收，方法已记录、场景尚未实现。 |
| 时间步长、渲染、输入响应和平滑分别影响运动 | 60FPS和速度正确就与参考同样流畅 | 核对起停、输入反应、朝向、相机、绕障碍与帧时突刺；未测当前因果前，不把固定步长或60Hz当确定修复。 |
| 体素数据、方块外观与渲染网格不同层 | 更多独立小方块或最近邻过滤独自解决精细度 | 可见面与相容面合并、重复件实例化须受材质/朝向/透空/照明约束；分块不改坐标/事实标识/连续路径，示例32³不直接成为长沙标准。没有网格改动或项目性能提升证据。 |

## 技能的采用与过滤

新读Game Studio两个参考，复用此前SKILL。采用模拟与渲染责任、显式相机、先捕获再检查提交/材质/主线程/GPU/解码/流送的方法；高密度UI与浏览器恢复责任分别考虑。没有为了目录迁移、GLB、Rapier或SpectorJS默认换引擎/装工具。工程方法不能替代游戏设计理论。

## 机制演算，非游戏实测

假设每帧消去剩余转向误差10%，error_next=0.9×error，t90=ln(0.1)/ln(0.9)/FPS：

| FPS | 100ms后剩余误差 | 达到90%变化量 |
| --- | ---: | ---: |
| 30 | 72.90% | 728.48ms |
| 60 | 53.14% | 364.24ms |
| 144 | 21.93% | 151.77ms |

若按时间常数tau=.12s使用blend=1-exp(-dt/tau)，理想t90约276.31ms。仅消除这个模型的帧率依赖，不证明参数适合本游戏，也不解决其他输入/碰撞问题。

R07规划约5377米道路路线，恒定8m/s、无等待绕行约11.20分钟。这不是整段已走或可达性证明，也不是“每30秒奖励”节奏依据。

同材质实心8³体素逐块六面为3072四边形，消除内部面为384，理想合并六侧为6；不计材质/光照/透明等条件，不是项目加速倍数。

## 已有证据的解释修订

参考R05普通游客合影→摄影→相册说明关系可连贯，不说明所有NPC应派合影任务。R07同张双塔照片判定说明规则与保存可一致，不证明玩家理解构图。40人移动只是短采样活动；近60FPS只是指定设备条件；模块协作是运行基础，均不自动升级为生活感、手感、全城生产或还原达标。

## 实际改进与边界

本轮学习修订制作及验收判断，没有改游戏、安装工具、增加真人或新实玩。已有方法足以用于制作，不以再集齐理论名称作为开工前提；新问题仍可引出新知识，不以此表限定范围。每次实施须说明改善核心问题的因果、依赖与失败后撤回什么；真实街角/连续经历可为检查单元，不替代全市目标。
